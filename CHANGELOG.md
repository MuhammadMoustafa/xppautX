# Changelog

What is new, what changed and what was fixed in xppautX, newest first. The
form is [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); each entry
ends with its card and issue (docs/roadmap.md, GitHub). A card that changes
what a user meets adds its line under Unreleased. How xppautX differs from
XPPAUT 8.0, area by area, is [docs/xppautx-vs-xppaut.md](docs/xppautx-vs-xppaut.md);
the bugs found in XPPAUT itself are in [docs/xppaut-findings.md](docs/xppaut-findings.md).

## [Unreleased]

- One registry-driven page menu, command palette and argument form; logical shortcuts with an XPPAUT preset, a named Windows menu and an annotation list with plot selection and dragging. The native menu keeps Quit and About. The `menu` ask, the one-letter shortcut layers, `key` with `menu`, `item` or `win`, and hello's `menu_names`, `command_table` and `windows` are gone: a key is a registry command through the keymap, and the keymap refuses a key that is the start of another in the same context. XPPAUT's sequences that began another's are split: `AH`/`AN`/`AI`/`AP`/`AT` (AUTO's Axes plot kinds, all the plot form), `IUF`/`IUA`, `FON`/`FOI`, `PP`/`PF`, `FDS`/`FDT`. Clear in AUTO sends the diagram's points again with the earlier branches marked (W517, [#581](https://github.com/MuhammadMoustafa/xppautX/issues/581)).

- The File menu's operations, the recording and its player, the keyboard shortcuts, the data-event subscriptions and the small tools are registry commands (W528, [#592](https://github.com/MuhammadMoustafa/xppautX/issues/592)): `session.open_model`, `reload_model`, `open`, `save`, `save_as`, `save_copy`, `import_settings`, `export_info`, `get_source`, `quit`, `get_state`; `recording.start`, `stop`, `add_note`, `open`, `play`, `pause`, `step`, `set_speed`, `seek`, `close`, `set_step_note`; `keymap.get`, `set`, `reset`; `events.subscribe`, `unsubscribe`; `tool.calculator`, `run_source_action`, `run_user_button`. Typed, named arguments, each ending in `done` with its result; the old `open`, `reload`, `session`, `record`, `play`, `keymap`, `data`, `equations`, `state`, `quit`, `action` and `userbut` forms are gone (unknown commands). `quit` is `session.quit` with `save` (false leaves at once, true saves first, left out asks), `data` is `events.subscribe` (it adds to what the client has; `events.unsubscribe` removes) and the program's first command is `session.get_state`, so a `--server` session now starts with `done` where it said `idle`. A model's path is `session.open_model`'s `file` (`--server`'s own input only; the page opens a recent model by its place in `hello.start.recent`). The File menu keeps its keys and asks as before.
- A branch of cycles whose period grows without bound ends where it ends, named and said: SNIC (saddle-node on invariant circle), Homoclinic or Heteroclinic (W518, [#582](https://github.com/MuhammadMoustafa/xppautX/issues/582)). When the period has grown over 5 points to twice its shortest and the orbit lingers within a millionth of its fastest speed of standing still, the equilibria it lingers near are found (Newton's method from the orbit's slowest points, Sing pts' settings) and their eigenvalues judged: one with a zero eigenvalue is a `snic` (mark SNIC), one saddle a `homoclinic` (HOC), two or more saddles in turn a `heteroclinic` (HEC); anything else still stops with "period growing without bound ..." and no new type. The branch stops there, the point is stored, labelled and marked like the others, and `autoinfo`'s `stop` (`why` `snic`, `homoclinic`, `heteroclinic` or `period_unbounded`) gives the period, the parameter and the equilibria; AUTO-07p and XPPAUT run on to MX or the step limit with no word. The two `ode_mu26` descriptions' `to_snic` runs now end on a SNIC (SmIapp 0.00634, period 4055; the blocked one SmIapp 0.0667, period 4974) instead of at their step limit.
- A saddle's invariant sets are drawn and exported whole: each branch of Sing pts' Draw Invariant Sets and of `equilibrium.export` with `shoot` starts at the saddle (the export at the clock it began at) and is stored whole, whatever `store_from` says. Before, the drawn branches lost their start near the saddle with a positive `store_from`, and the export's second branch started where the first ended and failed with the store_from error; the export leaves the session's time as it was (W533, [#598](https://github.com/MuhammadMoustafa/xppautX/issues/598)).
- The data browser, the values and the named sets are registry commands (W526, [#590](https://github.com/MuhammadMoustafa/xppautX/issues/590)): `browser.page` (the block of the table the page shows, answered at once even during a run), `browser.find`, `replace_column`, `undo_replace`, `tabulate_column`, `set_slice_start`, `set_slice_end`, `restore_full_slice`, `add_column`, `delete_column`, `load`, `export` (the data table, the model's output columns or what the plot shows, in a format named), `transpose` and `postprocess`; `value.set_parameters`, `set_by_formula`, `undo`, `redo`, `slide`, `configure_slider`, `remove_slider`, `save_file` and `load_file`; `set.apply`, `save_new`, `save_into`, `save_defaults`, `export`, `rename`, `delete` and `restore_defaults`, each with typed, named arguments (the scope and the state are named choices, the graph is `window`) and a `done` result. The old `browser`, `values`, `applyset`, `saveset`, `savedefaults`, `exportset`, `renameset`, `deleteset`, `restoredefaults`, `slide` and `slider` commands are gone, and `set` no longer takes a parameter (`value.set_parameters`; a formula is `value.set_by_formula`); `set` keeps the boundary conditions, the delays and the numerics no command has taken yet. The browser window's keys and the File menu's picks ask as before and call the same core functions, which return their errors as values: a Find, Replace, Table or Delete column of a name the data has not, a Transpose that reads past the data (XPPAUT clamped it), an Add column of a name the data has and a First row not before the last (or a Last before the first) are refused saying why, and Restore keeps all the data again and replots it (it replotted the rows between First and Last). A registry command carries no `replace` decision: replacing a file asks, and a No is an error. `--silent` writes its `--qsets`/`--qpars`/`--qics` file and its output.dat itself, no longer through protocol lines. The page sends the new commands; the repository's recording uses none of the old ones.
- AUTO's commands are on the command registry (W516, [#580](https://github.com/MuhammadMoustafa/xppautX/issues/580)): `auto.run` (kind `equilibrium`, `periodic`, `two_parameter`, `fixed_period`, `bvp`, `homoclinic`, `heteroclinic`; `switch`; a start by `label`, by `type` and `index`, or the current state; the Numerics by their names for that run; `step_size`'s sign the direction), `auto.grab`, `auto.configure_numerics`, `auto.configure_plot`, `auto.configure_marks`, `auto.set_threads`, the views (`auto.set_display`, `auto.pick`, `auto.scroll`, `auto.zoom`, ...), the exports and the diagram files, each ending with `done`; the old `{"cmd":"auto","op":...}` forms are gone (the keys stay for the interactive menus). The page's Run button opens a dialog of the kinds the grabbed point takes. A model whose equations use `t` is refused with each equation's file and line (AUTO evaluates at t = 0: [finding 95](docs/xppaut-findings.md#95-auto-evaluates-the-equations-at-t--0-without-a-word)). The shipped recording was migrated by `tools/migrate_w516_recording.py`.

IID's six levels are named (`none`, `little`, `normal`, `start_jacobian`, `extensive`, `debugging`) and MXBF's sign is a setting of its own, `switch_one_direction`. The branch kinds in diagram files take the point types' names (`fold`, `cycle_fold`, `neimark_sacker`). AUTO's names and XPPAUT's (`@ ntst=`, `parmin`, ...) are read on import only; the repository's models, descriptions, baselines and recording were migrated by `tools/migrate_w531_settings.py`; no number changed.
- A graph's curves, frozen curves, axes, exports and markers are registry commands (W524, [#588](https://github.com/MuhammadMoustafa/xppautX/issues/588)): `plot.add_curve`, `edit_curve`, `delete_curve`, `delete_all_curves`, `freeze_curve`, `edit_frozen`, `delete_frozen`, `delete_all_frozen`, `set_frozen_legend`, `import_bifurcation`, `clear_bifurcation`, `set_auto_freeze`, `export_pdf`, `export_svg`, `export_data`, `set_axes_origin`, `set_colormap`, `set_2d`, `set_3d`, `set_3d_view`, `set_shifted_axes`, `variable_vs_time`, `add_data_markers` and `set_variables`, each taking the graph by name, with typed arguments (colours quoted, line styles and colour scales by name, booleans for flags, plot coordinates), what is left out kept, and a result; the Curves, Axes, Numerics and `3` forms call the same core functions. The old `colormap` and `plotvars` commands are gone. A frozen curve's `slot` is in the `marks` event. Add markers refuses rows past the stored data instead of reading beyond them ([finding 96](docs/xppaut-findings.md#96-markers-on-the-data-read-rows-past-the-stored-data)), a rUelle shift, an axes font size outside 1 to 100 and a legend key or name over its width are refused instead of cut or clamped.
- The kinescope, the animation and the array plot are registry commands (W527, [#591](https://github.com/MuhammadMoustafa/xppautX/issues/591)): `kinescope.capture`, `reset`, `play`, `autoplay`, `export_frames`, `export_gif`; `animation.open`, `load`, `play`, `reset`, `set_frame_skip`, `export_frames`, `set_live_draw`, `grab_point`, `set_speed`, `step`, `seek`, `pause`, `faster`, `slower`; `array_plot.open`, `redraw`, `configure`, `fit`, `range`, `export_pdf`, `export_gif`, `scroll`. The `ani` and `aplot` commands are gone. A dragged grab point is one `animation.grab_point` at the release, the animation's frame saving writes at once (it asked first, then waited for Go), `array_plot.scroll` takes the first row shown instead of pixels, a frame skip below 1 and a colour scale with `z_min` not below `z_max` are refused, and a command that has nothing to work on says why. The `aplot` event carries `first_row`.
- Equilibria, nullclines and direction fields use typed registry commands in the page, protocol and recordings; forms become arguments, guesses use named graph coordinates, and each operation returns its declared result with `done`. Nullcline export writes the current pair in the named data format (W522, [#586](https://github.com/MuhammadMoustafa/xppautX/issues/586)).

- AUTO's point types have names (`branch_point`, `fold`, `hopf`, `period_doubling`, `neimark_sacker`, `end`, `no_convergence`, `user_point`, `cycle_fold`, `cycle_branch_point`, `bogdanov_takens`, `resonance_1_1` ... and the others) instead of two-letter codes everywhere xppautX shows or writes one: the page, the protocol (`info.sym`, a label's type, `grab` by `type`, `special_points`), the session files, CSV exports, menus and the log's AUTO table. Each name has one label ('Andronov–Hopf') and one mark (`AH`, drawn at the point) in one table, sent by hello as `point_types`. The codes stay in AUTO's own files and in the imports of AUTO-07p and XPPAUT (W519, [#583](https://github.com/MuhammadMoustafa/xppautX/issues/583)). A migration (`tools/migrate_w519_point_names.py`) renames the repository's own descriptions and recording.
- The rest of window and annotation on the command registry (W523, [#587](https://github.com/MuhammadMoustafa/xppautX/issues/587)): `window.set_bounds`, `window.zoom`, `window.zoom_out`, `window.fit`, `window.reset_default`, `window.scroll`, `window.set_display`, `window.redraw` and `window.clear` set, move and draw a graph's view in plot coordinates, and `annotation.list`, `add_text`, `add_arrow`, `add_pointer`, `add_marker`, `edit`, `move`, `delete` and `delete_all` replace the `annotation` command (an annotation is named by `annotation_id`, since `id` is the request's own). The `display`, `redraw` and `annotation` commands and the main menu's `restore` and `erase` items by `key` `menu`/`item` are gone; the page's plot tools gain Redraw plot, Clear plot and Add text, arrow, pointer and marker buttons. Zoom in and out take their box in plot coordinates, as doubles (the window's key path kept pixels and floats).
- One way to hide, show and destroy any window (W515, [#579](https://github.com/MuhammadMoustafa/xppautX/issues/579)): `window.hide` and `window.show` keep a window and everything in it, `window.destroy` (W353's `window.close`, renamed; it no longer doubles as AUTO's hide) deletes it, and `window.list` lists every window with whether it is shown. They hold for graphs, AUTO views and now also the data browser (`browser`), the animation (`animation`) and the array plot (`array_plot_1`), whose names are fixed and reserved; the `ani` and `aplot` close operations are gone. Destroying a graph that holds texts, arrows, markers or frozen curves asks first (a script sends `confirm` true). The page's Hide AUTO and Show AUTO send them, a new `windows` event tells the page what is shown, and a session file keeps hidden graphs, AUTO views and the data browser (`views.txt` lines read `view "name" shown|hidden ...`).
- Animations use `.anix`, with the model grammar, keyed shape fields, quoted colours, named styles and trailing ranges. Models and animations link by base name, sessions bundle the animation, and `.ani` opens through a one-time converter. Permanent shapes keep their colours as well as their coordinates (W520, [#584](https://github.com/MuhammadMoustafa/xppautX/issues/584)).
- The run, initial-condition and boundary-value operations are registry commands (W521, [#585](https://github.com/MuhammadMoustafa/xppautX/issues/585)): `run.initial`, `run.last`, `run.old`, `run.shift`, `run.backward`, `run.continue`, `run.steady`, `run.range`, `run.double_range`, `run.dae_guess`, `run.shoot`, `run.configure` (the integration's numerics, checked together and all or nothing), `run.abort`; `ic.set`, `ic.at`, `ic.mouse_stream`, `ic.load`, `ic.formula`, `ic.array`, `ic.from_data_row`; `bvp.solve`, `bvp.solve_periodic`, `bvp.solve_range`, `bvp.configure`. Typed, named arguments with the session's current setting for each one left out, and a `done` with the run's status, rows and time. The old `continue`, `steady` and `abort` commands, the data browser's Get key's own code and `set` of an initial condition or of those numerics are gone; the Initialconds, Bndry Value and Numerics menus, their keys and the XPPAUT button sequences (`ig`, `br`, `ut` ...) stay and ask as before, then call the same core functions as the commands (`ic.set`, `ic.load` and `ic.formula` only set the values; the menu's New, File and formUla still set then run). `run.configure` also takes the Volterra points (`vmaxpts`, `autoeval`), the CVODE band (`bandlo`, `bandup`) and the delay's guesses and grid (`delay_real_guess`, `delay_imaginary_guess`, `delay_grid`), each only where it applies, all or nothing with the rest. A run that ends early (an event's `arret`, a section) says so in its `done` (`ended_early`). The toolbar's Run from initial, Run from last state, Run to steady state and Continue, and the Values panel's fields, send the new commands.
- The analysis and table operations are registry commands (W525, [#589](https://github.com/MuhammadMoustafa/xppautX/issues/589)): `analysis.seed_random`, `stochastic_integrate`, `load_stochastic_run`, `load_stochastic_mean`, `load_stochastic_variance`, `histogram`, `reload_histogram`, `histogram_2d`, `fourier_series`, `power_spectrum`, `fit_curve`, `statistics`, `lyapunov_exponent`, `autocorrelation`, `cross_correlation`, `spectral_density`, `poincare_map`, `phase_space_torus`, `color_coding`, `adjoint_compute`, `adjoint_interaction`, `adjoint_load`, `adjoint_load_orbit`, `adjoint_load_interaction`, `adjoint_configure`, `adjoint_range`, and `table.edit`, `table.view_in_browser`, with typed, named arguments (a choice by its word: `psd_x`, `hann`, `direct`, `max_min`, `velocity`; an argument left out keeps the session's setting) and a `done` with the result. The Stochastic, Adjoint, Poincare map, Phase space, Color code and Tables menus and their keys stay and ask as before, then call the same core functions. The `browser` command's `postprocess` is gone: `--silent` runs the model's `@ postprocess` as the analysis command it names. A condition that is not a formula is an error (the histogram used to ignore it), the cross correlation's lags are refused beyond what the data allow (they were cut), a Stat of constant data has a variance of 0 (rounding could make it negative), viewing a table with more points than the data table has rows is refused (the rest was cut), and the 2D histogram and the spectral density refuse the bins and windows that overran their columns or divided by zero ([finding 98](docs/xppaut-findings.md#98-the-2d-histogram-writes-past-its-columns-when-its-bins-outgrow-the-storage), [finding 99](docs/xppaut-findings.md#99-a-spectrum-window-of-one-point-divides-by-zero)).

- A refused animation file leaves the working animation, selected filename, grabs and displayed frame intact. The existing reader stages the replacement and applies it only after validation; errors name the animation file and its physical line, including grab tasks and continued lines. Animation files use the model-file 512 MiB input budget; array expansion is checked and limited to 100000 commands per file (W507, [#571](https://github.com/MuhammadMoustafa/xppautX/issues/571)).
- Delay-differential runs take about 12% fewer instructions, with the same results to the bit (W514, [#578](https://github.com/MuhammadMoustafa/xppautX/issues/578)): the delay interpolation `polint` is straight-line code.
- The retained bundled CVODE solver has C++ interfaces in `xpp::cvode_solver`, with typed solver handles and reference outputs; its numerical operations are unchanged (W511, [#575](https://github.com/MuhammadMoustafa/xppautX/issues/575)).

- A plot text's style is a name, never a number: `normal`, `bold`, `italic` or `bold_italic` in the `annotation` command, the Text,etc dialog, the `marks` event and the session's `labels` (W532, [#597](https://github.com/MuhammadMoustafa/xppautX/issues/597)). A text's size is its own whole-number argument, `text_size` (0 to 4), on `annotation.add_text` and `annotation.edit`; `size` stays the real size of an arrow, pointer or marker. The `hello.text.style_count` field is now `hello.text_styles`.
- Every text, arrow, pointer and marker has an id and no fixed number (W513, [#577](https://github.com/MuhammadMoustafa/xppautX/issues/577)): the `annotation` command (replacing `text`) lists, adds, edits, moves and deletes any of them by id, in the plot's coordinates, without a click; the ids stay through other deletions and are saved with the session (`marks.setx` gains `next_annotation_id` and an `id` in each entry); XPPAUT's limit of 50 texts and 400 arrows, pointers and markers is gone (100000 of each). The page draws the marker shapes and arrow heads from the glyphs the core sends in `hello`, as the PDF and SVG do; the diamond marker is now drawn centred on its point, as the page drew it.
- Add the typed core command registry and named graph/AUTO windows: create, rename, select and close by name, server text input, strict entry-driven validation, text client ids, correlated `done` results and generated protocol documentation (W353, [#414](https://github.com/MuhammadMoustafa/xppautX/issues/414)); the page, sessions and recordings use names instead of numeric window handles, and the old Makewindow commands are removed.

- Every number of a table file is checked (W505, [#569](https://github.com/MuhammadMoustafa/xppautX/issues/569)): the point count, both ends and each value must be one finite number (a word, `nan` or `inf` is refused), and a bad one stops the load with the file, its line and the value, nothing applied. Before, a word or `nan` read as 0 or as an unchecked value, and the table kept it. The range `xhi-xlo` must also be finite.
- Every startup option is read once (W506, [#570](https://github.com/MuhammadMoustafa/xppautX/issues/570)): `--server`, `--browser`, `--web`, `--no-open`, `--port`, `--convert`, `--check`, `--yes`, `--help` and `--version` are in the command-line table with the load's options, so one pass checks them all. `--port` must be a whole number from 0 to 65535 (XPPAUT's `atoi` made a bad one 0), `--server` with `--browser` is an error, a misspelt option is refused even beside `--version` or `--help`, and `--convert` and `--check` refuse load options instead of ignoring them. `--quiet` and `--logfile` are no longer found by a second scan. What a load takes from the command line (the files, sets and switches) belongs to its model, so File > Open model and Reload no longer share a process-wide copy.
- The dense LU factorizations and solves of the CVODE, Stiff and Gear solvers run their row updates through the vectorized `xpp::subtract_scaled`, with the same results to the bit (W503, [#567](https://github.com/MuhammadMoustafa/xppautX/issues/567)): on a 400-state model CVODE and Stiff run faster (the timings on a shared machine: CVODE 20 to 40% less time, Stiff about 5%; Gear within the noise).
- A finite number is always sent as a number in the protocol: values between 1e308 and the largest double were sent as `null` by a custom cutoff, and now they are numbers, with NaN and the infinities still `null` (one rule in core/json_number.h, W509, [#573](https://github.com/MuhammadMoustafa/xppautX/issues/573)).
- Data files a user may have been sent are read within one budget (W504, [#568](https://github.com/MuhammadMoustafa/xppautX/issues/568)): a data file (`.csv`, `.csv.gz`, `.npz`) larger than 512 MiB, a gzip whose members together expand past it (a small file could exhaust memory) and an `.npz` array with more than 4096 columns, a dimension too large to count, or a shape its data cannot hold are refused whole, naming the file and why; a CSV or NPZ seed must be a whole number that fits an integer (before, text after the number was ignored and an out-of-range NPZ seed was cast blindly).

- Every numeric setting has its range, checked in one place (W494, [#558](https://github.com/MuhammadMoustafa/xppautX/issues/558)): settings that must keep an order (`min_step` at most `max_step`, `xlo` below `xhi`, `ylo` below `yhi`, the 3D box, a histogram's low below its high, the diagram's axes) are refused wherever they come from, with both names and values, at the file's line; `nplot` is 1 to 8, `dfgrid` and `histbins` at least 2, `torus_period` above 0, `rangestep` at least 1. The reset of a reversed window to -2..2, of a reversed box to -1..1, the clamp of `nplot` to 8 and the run-time `min_step > max_step` refusal are gone: they could no longer be reached. The Window and histogram dialogs and the direction-field grid use the same rules.
- The terminal shows only what the page cannot (W501, [#565](https://github.com/MuhammadMoustafa/xppautX/issues/565)): with a page open (window and browser modes) the page's log takes everything, AUTO's table included, and the terminal that started xppautX gets its warnings and errors (the page may be closed), the browser's address and, with `--verbose` or `--debug`, the whole log. Before, the terminal repeated the whole log, AUTO's table among it. `--server`, `--silent`, `--convert` and `--check` are unchanged.

- Fix three inherited numerical bugs (W496, [#560](https://github.com/MuhammadMoustafa/xppautX/issues/560)): Stiff stops with a placed error when its step matrix is singular; the cross spectrum averages exactly the windows it divides by; sampled events at a step's exact endpoint fire once, including sign-zero events. These deliberately correct XPPAUT's results (findings 79, 85 and 87).
- The remaining stop messages say why: a Poincare map with no crossing names its section and interval, Monte Carlo reports attempted and converged guesses and distinct equilibria, and a failed manifold returns one placed error. Periodic AUTO no-convergence messages include a singular reduced-system pivot; a zero pivot error includes its value and threshold. Short AUTO solution input names its label (W498, [#562](https://github.com/MuhammadMoustafa/xppautX/issues/562)).

- AUTO checks its start before continuation: a steady-state start whose residual is above EPSU is first refined by Newton (the Sing pts settings), and is refused only when Newton does not converge, naming the worst equation, its residual and the Newton settings. Par Min/Max bound only the first parameter, as AUTO-07p does. Parameter and norm bounds, duplicate two-parameter axes and incompatible restart kinds are errors. Norm Min/Max remain available, with defaults 0 and 1e100 (W495, [#559](https://github.com/MuhammadMoustafa/xppautX/issues/559)).
- The remaining choice values have names: native `findext` uses `both`, `maximum` or `minimum`; SuppBP is a boolean and a checkbox; native AUTO diagram files write calculation and curve names. Internal event targets, browse sequences and command IDs use enums, and an omitted marks list uses optional presence (W499, [#563](https://github.com/MuhammadMoustafa/xppautX/issues/563)).

- Continuation model options and forms use AUTO’s shared numeric rules, including ordered limits and signed step magnitude; invalid inputs fail before application instead of being repaired during a run. Native colours are always quoted, including "foreground" and CSS names; marker forms offer named shapes (W494, [#558](https://github.com/MuhammadMoustafa/xppautX/issues/558)).

- Equilibria, shooting, fits, nullclines and the histogram say why (W489, [#553](https://github.com/MuhammadMoustafa/xppautX/issues/553)): Sing pts that finds no equilibrium names the start, what stopped Newton's method (a singular Jacobian, the search box, `max_iterations`, with the setting and its value, the last change and `newton_tolerance`) at the equation's model line, and an eigenvector it cannot find for a manifold says which eigenvalue and why instead of "Failed to compute eigenvector"; the delay equations' root search and Monte Carlo's manifolds say theirs; a shooting that fails names the iterate and carries the integrator's own error (the variable, the time), "Maximum iterates exceeded" gives `bvp_max_iterates` and the residual, and a Range Shoot names the parameter value and step it stopped at; a fit that ends at `maxiter` says so with chisq and the last change against `tol`, and a singular matrix names the iteration, lambda and the parameter; a nullcline or direction field whose right-hand side fails names the grid point; Fourier, Power and spectrum on a run that stored under 2 rows, a model with one variable, or a window longer than the data say so (the post-processing after a run used to do nothing). `nullclines.file` is written in the data format its extension names (`.dat`, `.csv`, `.csv.gz`, `.npz`) as a row per segment (`nullcline`, `x1`, `y1`, `x2`, `y2`), replacing the gnuplot text of XPPAUT's `nullclines.dat` (a deliberate change); a nullcline's storage grows with its segments, with no 10000-segment cap. ## [0.1.0-beta.1] - 2026-10-08

First public beta of xppautX, a modernised XPPAUT 8.0: the same equations, solvers and AUTO, with a new interface.

- **Your models work.** XPPAUT `.ode` files are converted once to `.odex` when opened; results match XPPAUT's, and are the same bit for bit on Windows, Linux and macOS.
- **A new interface** in the desktop window or a browser: a command list with search (Ctrl+K), keyboard shortcuts you can change (Help > Change shortcuts), a toolbar you can pin commands to, and plots, values, tables and AUTO diagrams as live panels.

- **Sessions:** save everything with Ctrl+S (a dot in the title shows unsaved changes), Save as, Save a copy, Reload keeping your values; recordings (`.recx`) replay a whole analysis.
- **Headless and scripting:** `--silent` runs and a JSON protocol on stdin/stdout or HTTP.
- **Settings have descriptive names** (`total_time`, `transient_time`, `storage_rows`, ...); XPPAUT's old words are accepted only when converting a `.ode` or on the command line.

Known limits of this beta: the macOS builds are tested by the automatic checks only, not by hand; the installers are not signed, so Windows SmartScreen or macOS Gatekeeper may warn; the one-letter XPPAUT key sequences are an optional preset (off by default).

- A model's `@` options all take effect, so a model that set `newt_iter`, `newt_tol`, `jac_eps` or `poistop` now runs with them ([finding 1](docs/xppaut-findings.md#1-model-options)) (W119, #170)
- `.ode` keeps its fixed quantities fixed; only `.odex` derives them (W80, #129)
- A setting you edit during a run (parameters, initial conditions, numerics, AUTO's values) applies to the next run, not the one running (W106, #155)
- Menu items and keys are enabled by what they do (control, view, setting, ...) from one table in the core, so Abort, Quit and view commands work while a run computes (W95, #144)
- Quitting asks "Save this session first?" without stopping a computation, a plain quit says bye and exits normally, and browser mode ends 2 s after its tab closes (W59, #107; W110, #162; W112, #164; W108, #160)
- Faster live runs and large plots: a run ends with a small end event, columns are encoded in place, names are resolved once (W122, #173)

- The Linux release is built on Ubuntu 26.04 and needs its glibc or newer; an older Linux builds from source with `tools/build_linux.sh`, which installs what the build needs (README "An older Linux")

Silent playback keeps plain-name outputs in the launch folder; existing files require terminal confirmation within 60 seconds (EOF or timeout stops playback), or `--yes`. (W156, [#208](https://github.com/MuhammadMoustafa/xppautX/issues/208)).

- `.autox` and `.autoset`: AUTO's Save diagram saves the session (`.snapx`) and Load opens one; AUTO settings, diagram, views and orbits live under its `auto/` members. Reload keeps AUTO's settings without a separate file (W155, #207)

- The options file: a model's `option` line is refused at load with the line named, and `default.opt` is never read; write the settings as `@` lines, as XPPAUT in effect already required ([finding 4](docs/xppaut-findings.md#4-model-options)) (W139, #191)

## [0.1.0] - 2026-09-28

The first release of xppautX, a fork of XPPAUT 8.0 with no X11: one program
for Linux (x64), Windows (x64) and macOS (Apple silicon and Intel).

### Added

- `xppautX model.ode` opens the front end in a window of its own: WebView2 on Windows, WKWebView on macOS, WebKitGTK 4.1 on Linux (elsewhere it names what to install and uses your browser); `--browser` serves the page to your browser
- `-silent` runs a model headless and writes `output.dat`, as XPPAUT does
- `--server` speaks the JSON protocol on stdin/stdout ([docs/protocol.md](docs/protocol.md)), the interface the page and scripts use
- The source of each binary (GPL v2) is attached to the release

### Changed

- What differs from XPPAUT 8.0, by area, is in [docs/xppautx-vs-xppaut.md](docs/xppautx-vs-xppaut.md); the bugs found in XPPAUT's own code and fixed here are in [docs/xppaut-findings.md](docs/xppaut-findings.md)

### Removed


- The X11 front end (the page replaces it)

Linux needs glibc 2.39 or newer (Ubuntu 24.04, Debian 13, Fedora 40 and
later); macOS 13.3 or newer. The macOS and Windows binaries are not signed, so
the system asks you to allow them the first time (macOS: `xattr -dr
com.apple.quarantine` on the unpacked folder, or right-click > Open; Windows:
SmartScreen's "More info" > "Run anyway").
