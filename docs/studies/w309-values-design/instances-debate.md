## Round 1: Astra

1. **Unfilled inputs — disagree with automatic zero (open point 2).** A missing initial value and a missing connection are different scientific mistakes. Zero voltage, concentration or presynaptic drive may produce plausible but unintended results. Modelica’s unconnected-zero rule concerns **flow variables**, not arbitrary inputs. ([Specification](https://specification.modelica.org/maint/3.6/connectors-and-connections.html)) Make `input u` required; make `input u = 0` explicitly optional. Standalone execution follows the same rule. Aggregate missing-input diagnostics by declaration and instance range, retaining every affected name.

2. **Coupling needs an evaluation contract — modify.** Filling a slot must define a continuous expression evaluated at the solver’s current trial state, including intermediate stages, Jacobian evaluations and AUTO—not an assignment performed once or once per output row. Build a dependency graph spanning inputs and computed quantities; evaluate dependencies first and reject algebraic cycles with their source locations unless explicitly routed through existing algebraic-equation machinery. Mutual voltage coupling between differential states is valid; mutually dependent instantaneous inputs may not be. This distinction is missing and matters more than syntax.

3. **Inputs belong to the component — agree; arbitrary equation injection — disagree (open point 1).** The cell should declare where external influence enters. Adding directly to any derivative bypasses capacitance, area scaling and the model’s sign convention. Keep bindings restricted to declared inputs; document their physical meaning, units and sign even before implementing unit checking. A reusable gap-junction component should calculate one current and contribute opposite signs to its endpoints. Modelica connectors encode conservation; this proposal provides directed signals and does not automatically enforce it. ModelingToolkit likewise distinguishes composition from extending a model’s equations. ([Composition documentation](https://docs.sciml.ai/ModelingToolkit/stable/basics/Composition/))

4. **Only `+=` for continuous contributions — agree, but reject “in any order” (open point 3).** Floating-point addition is not associative: `1e16`, `-1e16`, `1` demonstrate why rearrangement changes results. Specify deterministic source/expansion order and reduction grouping across platforms. Keep duplicate `=` and mixed `=`/`+=` errors. Define nonzero defaults explicitly: my preference is that a default applies only when there are no bindings; otherwise use the single `=` expression or the sum of `+=` contributions from zero. Bias belongs in the cell equation. Recompute the sum on each evaluation; never accumulate across timesteps. `-=` adds no expressive power; multiplication and division belong inside expressions.

5. **Continuous contributions and events need separate semantics — modify (open points 3–4).** An event increment changes persistent state; an input contribution defines an instantaneous value. Brian2 explicitly separates summed variables from `on_pre` updates, and even restricts multiple `Synapses` objects targeting one summed variable—evidence that ownership needs defining. ([Brian2](https://brian2.readthedocs.io/en/stable/user/synapses.html#summed-variables)) Allow events to update synaptic states, with inputs reading their resulting currents; do not make events write continuous slots. Defer event compound operators to that separate contract. Permit constant-sized arrays of scalar inputs, validated elementwise. Defer function-valued inputs: pass presynaptic voltage into an ordinary synapse component whose equations own the kinetics, then bind its current to the cell.

6. **`using` must not silently redefine what other groups mean — modify (open point 7).** Suppose `bursting` changes `gca`, while `spiking` changes only `iapp`. If `using bursting` replaces the baseline, subsequently selecting `spiking` inherits bursting’s `gca`. That undermines the settled claim that a named regime has predictable values. Make `using` choose the initial group, while each group still resolves against its declaring component’s original default. Preserve the declaration-owning default separately. Reset-to-startup can restore the import selection explicitly. Also use typed syntax, such as `using { par: bursting, init: rest }`: the settled design permits identical names across kinds, making the proposed untyped list ambiguous.

7. **Imported options and instance menus — modify.** The [settled debate](../../../docs/studies/w309-values-design/debate.md) allows imported options only on explicit selection; the proposal’s “without `using`, use the file’s defaults” must not accidentally activate them. Instances share one integration method, timestep and RNG configuration. Restrict instance `using` to `par` and `init`; offer imported options as explicitly global settings actions. Keep scoped parameter/initial selection, but replace a flat menu of thousands of qualified groups with an instance selector, searchable group selector and atomic population/range application. Show mixed selections. Define parent-group scope explicitly: I favour resetting its namespace subtree, with that scope visible.

8. **Presets cannot yet express a network configuration — modify.** `using` supplies construction-time choices; a runtime preset supplies an experiment configuration. They serve different purposes, but should use the same resolver. The settled preset permits one reference per kind, so it cannot simultaneously choose `c1.bursting` and `c2.spiking`. Permit one reference per **kind and nonoverlapping instance scope**, rejecting parent/child overlaps rather than relying on application order. Resolve the whole transaction before applying settings/parameters and evaluating initials. Parameter-only selection should retain the settled rule of preserving existing initial numbers.

9. **Import ranges — agree, but this is a real grammar and naming change (open point 5).** The [parser](../../../core/odex_parse.cpp#L1163) supports indexing but no member access after an index; imports explicitly reject ranges. Existing [arrays](../../../docs/odex.md#L362) turn `x[3]` into `x3`. For consistency, lower `c[3].v` to canonical `c3.v`, reject collisions with explicitly declared `c3`, and preserve indexed display metadata. Support nested indexed segments through one structured name parser. Keep constant bounds, positive steps and index-bearing diagnostics. State the boundary limitation: the proposed chain fails for `n=1` because existing `2..1` ranges are errors; either document `n>=2` or deliberately revise empty-range semantics.

10. **Existing `network` operators must compose with instances — modify.** This cannot become a parallel coupling subsystem. [Amari](../../../examples/ode/amari.ode) uses convolution; [tstdelsp](../../../examples/ode/tstdelsp.odex) uses sparse and delayed sparse coupling. Their implementation addresses variables through `root + offset` in [simplenet.cpp](../../../core/simplenet.cpp#L952). Instance-major storage makes `c1.v,c1.w,c2.v,c2.w` unsuitable as a contiguous voltage vector. Add an explicit population-field view resolved to variable indices, and let existing network operators consume it. Preserve their numerical reduction order. Do not “fix” this by silently reordering states and data columns.

11. **Ten thousand cells is not a resource budget — modify (open point 6).** Current [limits](../../../core/odex.h#L45) include 256 imports and 100,000 expansions per statement. Naively repeating imports therefore fails well before 10,000 cells; nested ranges can also multiply otherwise legal expansions. Parse each source once per load, instantiate separately, and budget cumulative statements, expression nodes, states, edges, tables, output storage and solver workspaces with checked arithmetic before allocation. Ten thousand cells with three states and ten thousand double-precision samples already require roughly 2.4 GB for state samples alone. Measure sparse and dense cases, compilation, RHS cost, memory and UI responsiveness; include AUTO’s allocations.

12. **Protocol, conversion and transactional loading are release requirements — modify.** Publish canonical names, instance membership, group scope and input-binding metadata from the core; clients must not infer hierarchy by splitting labels. Keep inputs unrecorded unless explicitly exposed through `aux`. Define stable instance/declaration column order and preserve the protocol’s column identities. The [converter already avoids transformations that reorder columns](../../../docs/odex.md#L790): retain flat `.ode` equations and `special`→`network` conversion rather than guessing component boundaries. Check numerical baselines, recordings and snapshots. Resolve imports, ranges, every group and every binding before committing a model. Errors need original file/line/source, import chain, expanded indices and both conflicting declarations. Reuse existing path confinement and reader limits; caching must not bypass them. Reject expansion bombs before allocation. Test identical behavior across window, server, silent, check and convert modes.

13. **Questions only the maintainer can decide:**
    - Should an unwired input prevent loading unless its author explicitly supplies a default?
    - Should `using` mean initial selection, as recommended, or intentionally rebase every subsequent group?
    - Is this release limited to continuous coupling, with event delivery and function-valued ports explicitly deferred?
    - May presets select multiple disjoint instance scopes, and should parent groups reset their entire subtree?
    - Is a measured 10,000-cell sparse network a release acceptance target, and which solver, recording and AUTO workloads must it support?
