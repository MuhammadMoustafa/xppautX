# W659: does every command-line switch earn its place? (#732)

A study, no code changed. It builds on the maintainer's decision of 2026-11-08 while settling W652 question 6 ([w652-options-audit.md](w652-options-audit.md)): **"The file wins."** The model file is the one place a model's run is described; a switch that repeats what the file can say is to go; the seven rows a windowless run reads (`nullclines.draw`, `direction_field.draw`, `export.format`, `output.data_file`, `nullclines_file`, `after_run`, `after_run_file`) stay in the file. This study lists every switch of `xppautX --help` (built and read: `./xppautX --help`), with core/comline.cpp's table (`my_cmd[]`, lines 39-80) and xppautx_main.cpp, and proposes what each becomes. The maintainer decides; the implementation cards follow.

## Summary

37 switches (the 27 a load takes and the 10 program switches; `-h`, `-y` and `--web` are second spellings of three of them). Proposals: **10 drop** (the file or the preferences already say it), **5 move** (4 need a new row in the file first, then the switch goes; 1 goes to the environment), **22 keep** (a mode, a query that prints, the choice of what a run starts from, a per-run override of a preference). Three more things the study found:

- `--help` prints a switch that does not exist: `--auto` (xppautx_main.cpp:131); `./xppautX --auto` answers "no such option --auto". It is `--yes`'s old name; the line goes whatever else is decided.
- `--help` says `--plotfmt svg|ps`, but `ps` only imports as `pdf` (the row's `foreign`, model_options.cpp:858; the choices are `picture_format_names`).
- Only `json_silent.cpp` reads 12 of the 27 load switches (`--outfile`, `--noout`, `--mkplot`, `--equil`, `--qsets/--qpars/--qics`, `--internset/--uset/--rset`, and the seven rows' own batch work); a run in the window reads none of them, and `--convert`, `--check` and `--options-schema` refuse them (xppautx_main.cpp:280-296, `load_options`).

Questions for the maintainer, most important first, after the table.

## Proposals

### 1. Where the seven batch rows live, in the file and in the UI

Today four sit in `output` (`data_file`, `nullclines_file`, `after_run`, `after_run_file`, model_options.cpp:881-911), `export.format` sits in `export` and two (`nullclines.draw`, `direction_field.draw`) in `plot` beside the colours and the grid. Only `json_silent.cpp` (and `batch_plot_name`, many_pops.cpp:288, `do_batch_*`) reads them; a run in the window writes no output.dat, yet File > Output shows four of them there.

Proposed: **one `output` group of everything a windowless run writes**, in this order: `data_file`, `write_data`, `picture_file`, the nullclines' draw and file, the direction field's draw, `after_run`, `after_run_file`, `equilibria.export` (the two draw rows are what a run computes and saves, so they come with it), the picture's colour and font size staying in `export` (they also serve the window's Export dialog). One panel, named after the group, whose first line says "Applies to a run without a window (`--silent`); a run in the window writes none of these." The panel is shown always (the rule: every option has its place) but each field is dimmed in the window with that line, never hidden. `nullclines.draw`/`direction_field.draw` keep their *window* meaning in `plot` if the window also draws after a run (graf: they are what the first view starts with); if they do not, they move whole into `output` and `plot` loses two rows. That is Q2's check.

**The picture's format from a file name's extension**, as the data file's: today `--mkplot` makes `<model><set>.<format>` (batch_plot_name, many_pops.cpp:288: no choice of name) and the format is a second row (`export.format`: pdf or svg). One row `output.picture_file` ("name.svg") replaces `--mkplot`, `--plotfmt`, `export.format` and the name rule: empty means no picture, the extension picks the writer (`find_image_format_by_extension`, which json_silent.cpp:156 already calls for the same word), an unknown extension is a load error at the row. It is the same rule `data_file` follows (named from the model's folder, `own_file`). With internal sets, each set's picture needs a name: `{set}` in the file name (as the data file is named after the set without `--outfile`, json_silent.cpp:122) is the one place that must be designed (Q1).

### 2. An XPPAUT model's switches once a switch is gone

XPPAUT's switches live in the command line of a shell, not in the `.ode`, so there is nothing in an `.ode` to map; the question is what `xppautX model.ode -outfile x -dfdraw 2` does. Options: (a) accept and ignore with a warning; (b) refuse with an error naming the switch and the row that replaces it; (c) `--convert model.ode` maps the old switches it is given to rows. **Proposed: (b), and (c) as `--convert`'s own optional second step**: the parser says `no such option --outfile` today for unknown words and already suggests the one-dash spelling (comline.cpp:127-132); a removed switch gets one more case of that error, "`--outfile` is `output.data_file` in the file: `xppautX --convert model.ode` writes the file, then edit". Never (a): ignoring a switch is the silent fallback the rules forbid ("No fallbacks"), and a script that passed `-outfile` would run and write no file. The XPPAUT spellings stay read where XPPAUT *files* hold them (`.ode` `@ outfile=`, `.set`), which is import and unchanged.

### 3. Can `--silent` then run any model or recording with no other switch?

For a model: yes for every run the file can describe, because every switch that changed *what* a run writes or computes (`--outfile`, `--noout`, `--mkplot`, `--plotfmt`, `--dfdraw`, `--ncdraw`, `--equil`, `--newseed`) became a row, and what stays is *which* inputs (`--setfile`/`--parfile`/`--icfile`, `--uset`/`--rset`) and the queries. For a recording `name.recx --silent`, it already needs none (xppautx_main.cpp:304). What a bare `--silent` cannot do is a second run of the same file with another data file name or another set; that is the point of the decision (the file says the run) and of the switches kept in Q4 and Q5. Two edges to say in the help: `--silent` on a `.snapx` is an error (xppautx_main.cpp:306-311), and with sets and no `run_sets` row it runs all of them (comline.cpp:299, `use_intern_sets = 1`).

## Questions for the maintainer, most important first

1. **The picture's name and format: one row `output.picture_file`?** Evidence: `--mkplot` + `--plotfmt` + `export.format` are three things for one file; the name is made, not chosen (many_pops.cpp:288, `<model><set>.<format>`, at most 100 characters of each, so a long model name is cut); the data file already takes a name from the file (`output.data_file`) and its format from the extension. Proposed: one row, the extension picks the format, `{set}` in the name for a run per set (or the set's name appended, like the data file); `export.format` and both switches go; `ps` becomes an error on a picture file name (XPPAUT's `ps` imports as `pdf`, as today).
2. **Do `nullclines.draw` and `direction_field.draw` do anything in the window?** The decision keeps them as batch rows; if the window only draws them on a command and never after a run, they belong whole in `output` and `plot` loses them. I read their window use only through json_silent.cpp and the first view's seed; the card must settle it by a run before moving them. Proposed: move to `output` if no window code reads them.
3. **Is bare `--silent` (no other switch, a model or a recording) the supported way to run a model unattended?** Evidence above; it rests on Q1 and the four new rows (`write_data`, `picture_file`, `equilibria.export`, `seed_random`). Proposed: yes, and the help's `--silent` line says "a headless run of what the file says (the `output` group)".
4. **`--setfile`, `--parfile`, `--icfile`: keep, or drop?** They name another *input* file per run, in XPPAUT's formats, so the file cannot say them; they are the only way a script re-runs one model from many starting points without a new `.odex` (6 tools/tests files use `--setfile`). Proposed: keep all three (the importer's job, "importing a foreign format is fine"); the alternative, one `.odex` per start, is more files for the same run.
5. **Sets and queries: three plus three switches into two?** `--internset 0|1`, `--uset NAME`, `--rset NAME` are three ways to say "which sets"; `--qsets/--qpars/--qics` three ways to say what to print. Proposed: `--sets NAME,NAME` (and no switch at all runs the file's `run_sets` row, default all, so `--internset` and `--rset` go) and one `--query sets,pars,ics`. This is a rename of kept switches, so it needs its own card and a look at 4 files that use them; say no if the XPPAUT spellings must stay.
6. **`--readset`/`--with` and `--include`: drop outright?** They are the strongest repeat of the file (the option text a model's `options {}` already takes) and `--include` does nothing to an `.odex` (ode_read.cpp:906 is the `.ode` reader). Dropping them removes the per-run override (`--with "dt=0.01"`), the one thing a script loses; the substitute is a named set in the file (`set "fast" {...}`) chosen by Q5's `--sets`. Proposed: drop; `--anifile` too, except as `--convert`'s second file name.
7. **One name per thing for the program's own switches:** `--web` (= `--browser`), `-y` (= `--yes`), `-h` (= `--help`), and `--no-open` (browser mode that does not open a browser). Proposed: drop `--web`, keep `-h`/`-y` (a terminal convention, not our own name), and make `--no-open` a modifier of `--browser` only (today it alone selects browser mode, xppautx_main.cpp:317, which is two meanings).
8. **`--no-compile`, `--quiet`, `--logfile`: where do they go?** `--quiet` and `--logfile` are the preferences' `log_level` and `log_file` (W619); `--logfile` is used by 3 checks, which would set the preference through the environment's config folder or use `--debug` and stderr. `--no-compile` is a debugging switch used by 3 checks. Proposed: drop `--quiet` and `--logfile`; `--no-compile` an environment variable `XPP_NO_COMPILE` (the `XPP_` family is already how checks change a run, AGENTS.md "Memory").
9. **Existing scripts and docs:** removing 10 switches and renaming 6 touches 4-7 files each of tools/ and tests/ and 3-8 of docs/ (the "Used in" columns, a grep of `--name`); one implementation card per group of Q1/Q5/Q6/Q8 with the docs in the same commit, since docs/protocol.md and docs/manual are checked by CI.
